Badge

Rótulo inline de status. Comunica estado de um item sem ocupar espaço de botão ou campo. Componente único — nenhuma tela cria sua própria etiqueta de status fora do .kz-badge.

Causa sistêmica — por que este componente foi criado agora
Causa do sistema (Lia): O badge.css existia com prefixo .badge + aliases semânticos (.badge-ativo, .badge-stock-ok) sem padrão único. Cada alias era uma classe separada para o mesmo estilo — fonte de inconsistência visual e de manutenção.

Causa do processo (Helena): Sem variante numérica definida, telas criavam contadores com estilos próprios. A senhora cansada via badges de formatos diferentes para o mesmo tipo de informação — perdia a referência de o que significava cada cor.

Regras UX — Helena
✗
Badge não é botão — nunca tornar clicável
Badge comunica estado. Se a ação precisar de clique, usar botão ghost ou link explícito. Badge clicável confunde a senhora cansada: ela não sabe o que vai acontecer ao tocar.
✗
Máximo 1 badge por item de lista
Dois badges no mesmo card ou linha criam hierarquia dupla — qual estado importa? A senhora cansada não deve precisar comparar dois rótulos para entender a situação.
!
Cor não pode ser o único sinal de status
Badge sempre tem texto ou número junto com a cor. Nunca usar só cor para comunicar estado — daltonismo e telas com brilho baixo eliminam a distinção de cor.
✓
Badge numérico: usar apenas para contagem real
Contador circular só aparece quando há número significativo a mostrar. Zero pode aparecer como 0 em kz-badge--neutral se a ausência for informação relevante. Nunca esconder o zero quando ele muda a ação do usuário.
✓
Ícone no badge: sempre aria-hidden no SVG
O texto do badge já descreve o estado. O ícone é reforço visual — leitores de tela não devem lê-lo. Sempre aria-hidden="true" no SVG.
Como chega ao src/
Regra: copiar componente.css para src/presentation/shared/styles/badge.css e garantir @import './badge.css' em index.css.
