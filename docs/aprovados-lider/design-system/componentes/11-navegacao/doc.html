Navegação

Sistema de navegação do KZERA. Três elementos: Menu Button (abre o drawer), Drawer (painel lateral de seções), Screen Header (cabeçalho por tela) com variante Back Button para telas filhas. Componente único — nenhuma tela cria seu próprio cabeçalho ou botão de voltar fora do .kz-screen-header.

Causa sistêmica — por que este componente foi criado agora
Causa do sistema (Lia): O sistema de navegação estava fragmentado em três implementações sem prefixo .kz- e sem tokens: drawer.css (hardcoded rgba), PerfilTemplate.css (hardcoded) e kzera-home-topbar (inline). Cada tela criava variações visuais independentes do mesmo elemento — cabeçalhos com tamanhos, espaçamentos e sombras diferentes entre seções.

Causa do processo (Helena): Sem back button padronizado, telas filhas (detalhes, edição, confirmação) eram implementadas sem retorno visual claro. A senhora cansada perdia a noção de onde estava na hierarquia do app e tentava usar o botão físico do celular (nem sempre disponível no iOS PWA) para voltar.
Anatomia — três elementos
ElementoFunção
.kz-nav-menu-btn
Botão hambúrguer fixo (topo esquerdo). Sempre visível em telas raiz. Abre o drawer.
.kz-nav-drawer
Painel lateral deslizante. Lista seções do app + versão no rodapé. Escurece o conteúdo atrás.
.kz-screen-header
Cabeçalho sticky de tela. Contém menu button (ou back button) + título + ação opcional.
.kz-btn-back
Botão voltar para telas filhas. Substitui o menu button dentro de .kz-screen-header.

Regras UX — Helena
✗
Menu button nunca some em tela raiz
Telas de primeiro nível (Perfis, Itens, Configurações) sempre mostram o menu button. Removê-lo deixa a senhora cansada presa — ela não sabe como trocar de seção.
✗
Tela filha nunca mostra menu button — só back button
Em telas de detalhe ou edição, o menu button deve sumir e o back button deve aparecer. Dois botões de navegação no mesmo header confundem: qual volta? qual abre o menu?
✗
Drawer nunca fecha ao navegar por clique fora sem backdrop visível
O backdrop escurece o conteúdo e serve de botão de fechar. Sem ele, a senhora cansada não sabe que pode tocar fora para fechar o menu — e fica presa no drawer.
!
Título do header: máximo 20 caracteres visíveis
O título tem text-overflow: ellipsis. Mas nomes longos já cortados criam dúvida: "Importação de Transações Fi…" — ela leu o suficiente? Preferir títulos curtos e claros na definição de cada tela.
✓
Item ativo no drawer: sempre destacado visualmente
A classe .is-active indica onde a senhora cansada está. Sem esse destaque, ela pode clicar na seção que já está aberta — gerando uma reação de "por que não mudou?"
✓
Versão do app sempre no rodapé do drawer
Regra do design system KZERA: versão aparece no menu, login e cadastro de senha. Drawer é o ponto principal — o rodapé com .kz-nav-version é obrigatório.
✓
100dvh (não 100vh) para evitar barra de endereço iOS
No iOS Safari, 100vh inclui a barra de endereço — o drawer fica cortado na base. 100dvh usa a viewport dinâmica e mostra o rodapé corretamente no iPhone.

Como chega ao src/
Regra: copiar componente.css para src/presentation/shared/styles/nav.css e adicionar @import './nav.css' em index.css (após input.css, antes de feedback.css).

Migração: as classes .kzera-drawer* e .kzera-menu-button em public/styles/drawer.css devem ser substituídas pelas classes .kz-nav-* conforme cada view for atualizada. Não adicionar nada em public/styles/drawer.css.
