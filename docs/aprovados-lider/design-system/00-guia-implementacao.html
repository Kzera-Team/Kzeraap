Guia de Implementação CSS

Onde fica cada coisa no código. Antes de alterar qualquer valor visual — cor, tamanho, sombra, radius — leia este guia. Alterar no lugar errado cria divergência silenciosa entre o design system e o código vivo.

Como adicionar um novo token em tokens.css
Antes de adicionar: verifique se o valor que precisa já não existe. 98% dos casos o token certo já está na escala. Adicionar token novo sem necessidade fragmenta o sistema. 
/* 1. Abra tokens.css */
/* src/presentation/shared/styles/tokens.css */

:root {
  /* Encontre a seção correta e adicione o token */
  /* Exemplo: novo token de espaçamento */
  --space-14: 56px;  /* ações críticas — altura danger button */
}
Regra de nomenclatura:
· Cor Light: --kz-light-[papel]
· Cor Dark: --vv-[papel]
· Status: --kz-status-[variante]-[bg|text]
· Espaçamento: --space-[número na grade de 4px]
· Radius: --radius-[1-6|full]
· Sombra: --shadow-[0-3|accent|danger]
· Tipografia: --t-[xs|sm|base|md|lg|xl|2xl|3xl]

doc.html sempre inclui: seção "Arquivos do componente" com os caminhos reais no projeto, e seção "Tokens utilizados" listando cada --variável que o CSS do componente referencia. Sem isso, quem vai manter não sabe onde olhar.
Regras de ouro — nunca violar
✗
Nunca valor hardcoded em CSS de componente
Errado: border-radius: 16px — correto: border-radius: var(--radius-4)
Errado: color: #7B4DFF — correto: color: var(--kz-light-accent)
Errado: padding: 12px — correto: padding: var(--space-3)
Único lugar onde valor aparece diretamente é dentro de tokens.css.
✗
Nunca declarar variável de token fora de tokens.css
Se um componente precisa de um valor novo, o token vai em tokens.css primeiro. Variáveis CSS declaradas em arquivos de componente são invisíveis para o resto do sistema.
✗
Nunca alterar um valor sem atualizar o doc correspondente
Mudar --radius-4 de 16px para 18px sem atualizar 05-border-radius.html cria divergência entre o doc e o código. As duas fontes ficam erradas ao mesmo tempo.
✓
Sempre usar fallback no var()
Escrever var(--radius-4, 16px) em vez de só var(--radius-4). Se o arquivo tokens.css não for importado por algum motivo, o componente ainda renderiza com o valor correto e o problema fica visível sem quebrar.
✓
Todo arquivo CSS começa com comentário de contexto
Primeira linha: /* KZERA · [Nome] — [arquivo].css */
Segunda linha (se componente): /* Requer: tokens.css importado via styles/index.css */
Isso deixa claro de onde vêm os tokens e qual o escopo do arquivo.
Ordem de imports em index.css
/* src/presentation/shared/styles/index.css */
/* Ordem obrigatória — não alterar */

@import './tokens.css';   /* 1º sempre — define as variáveis */
@import './card.css';     /* containers genéricos */
@import './badge.css';    /* status e tags */
@import './metric.css';   /* cards de métrica */
@import './form.css';     /* containers de formulário */
@import './feedback.css'; /* toast, empty state, loading */
/* novos arquivos de componente compartilhado abaixo */
styles.css está fora desta ordem: o arquivo src/presentation/shared/styles.css (um nível acima da pasta styles/) é legado e não importa tokens.css. Qualquer coisa lá usa valores hardcoded. Não adicionar código novo ali. Migrar para componentes específicos conforme cada componente for documentado.
